# Тренажёр японских частиц (PWA)

Приложение для изучения японского (цель — N5): подставляешь частицу в предложение, ошибки автоматически попадают в дневник. Работает как PWA на GitHub Pages (ветка main), владелец пользуется им с телефона (Android, Chrome). Язык общения и интерфейса — русский.

## Файлы
- `index.html` — весь интерфейс и логика (одна IIFE), стили внутри.
- `data.js` — `window.BASE` (196 предложений) и `window.USE` (ключ правила для каждого предложения по индексу).
- `words.js` — `WORDS` (слова), `VERBS` (глаголы с формами, как они стоят в предложениях), `EXTRA_TOKENS` (です, имена, цитата). Только то, что есть в `BASE`. По этим спискам предложения режутся на слова (блок `TOKENS-BEGIN…END` в index.html) для «Собери предложение» и примеров. Добавил предложение с новым словом — добавь слово сюда, иначе `tools/check.js` упадёт.
- `sw.js` — кэш офлайн. При любом изменении файлов поднимай `CACHE` (`jp-particles-vN`), иначе на телефоне останется старая версия. Новые файлы добавляй в `FILES`.
- `manifest.json`, `icon-192.png`, `icon-512.png`.
- Талисман Юки: `yuki.js` (модуль: эмоции, кадры лица, движения, частицы), `yuki.css`, ленты кадров `yuki-happy/sad/wow/sleep.webp` (по 4 кадра 330×484 в ряд; порядок кадров описан в начале `yuki.js`). В index.html — слоты `data-yuki` и `mountYuki()` после каждой отрисовки. Реакции: `ok`, `bad`, `goal` (цель дня или 3 верных подряд), сон на главном экране после перерыва ≥2 дней (сама просыпается через 4,5 с). После `bad`/`goal`/`wake` Юки сама возвращается к улыбке (`BACK` в yuki.js).
- Новые ленты кадров: листы 2×2 из генератора нарезаются скриптом `tools/yuki_sheet.py` (нужны Python, Pillow, numpy, scipy) (вырезает нарисованную «шахматку», выравнивает по ногам). Лучше просить у генератора сплошной фон #FF00FF.
- `tools/check.js` — автотест без браузера: `node tools/check.js .`

## Что нельзя ломать
- Ключи localStorage: `jp_stats`, `jp_custom`, `jp_days`, `jp_settings`, а также `jp_words` (id = написание слова), `jp_verbs` (`m:` + словарная форма — значение, `f:` + форма — формы), `jp_build` (id предложения), и их формат `{w, c, seen}`. Менять формат только с миграцией.
- id предложений: `'b' + индекс в BASE` у встроенных, `'c' + время` у своих. Поэтому в `BASE` и `USE` записи только добавляются в конец, порядок не менять.
- Формат резервной копии: `{v:1, stats, custom, days, settings, words, verbs, build}`; старые копии без трёх последних полей должны загружаться.

## Формат предложения
`{t:"私＿学生です。", r:"わたし＿がくせいです。", a:["は"], ru:"Я студент.", n:"заметка (необязательно)"}`
- ровно один `＿` и в `t`, и в `r`; в `r` кандзи нет; уровень N5;
- `a` — все допустимые частицы (に/へ, から/に), из набора: は が を に で へ と も の や から まで か;
- ответ должен быть однозначным по переводу;
- для каждого нового встроенного предложения добавь ключ в `USE` (см. `USES` в index.html) или новый ключ с понятным объяснением. Объяснение должно описывать, после какого слова ставится частица, и подходить именно к этому предложению.

## Логика (кратко)
- Выбор предложения: непросмотренные вес 1.5, иначе `max(0.25, 1+2w−c)`; пул ошибок: `w>0 && c<3`; освоено при 3 верных подряд, верный ответ после подсказки не засчитывается.
- Рукописная сетка: блок `GRID-BEGIN…GRID-END`, фуригана — блок `FURIGANA-BEGIN…END` (подпись стоит только над клетками иероглифа). `tools/check.js` проверяет оба блока на всех предложениях.

- Разделы «Слова» (значение, список), «Глаголы» (значение, формы, список), «Собери предложение» (плитки + одна лишняя частица). Выбор вопроса тот же, что у предложений; ответы идут в цель дня и серию (`jp_days`).
- «Собери предложение»: верно, если порядок совпал с исходным или переставлены только куски «слово + は/が/を/に/で/へ/から/まで/も», а сказуемое осталось в конце (кроме фраз с 、).

## Выкладка
1. `node tools/check.js .` (должно быть ALL APP CHECKS PASSED).
2. Поднять `CACHE` в `sw.js`.
3. Коммит и push в `main`; Pages обновится через 1–2 минуты, на телефоне новая версия подтягивается со второго открытия.
Репозиторий публичный: личных данных сюда не класть.
